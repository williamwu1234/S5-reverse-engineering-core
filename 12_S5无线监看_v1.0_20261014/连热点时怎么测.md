# 连相机热点时，自己怎么测「一边录制一边发送图像」

> ⚠️ **为什么不能让我（远程协助）来测**：Mac 一连上相机热点 `S5-XXXXXX`，
> 家庭网络就断了，远程会话与 DSH 界面都会掉线。所以这一步必须你自己跑。

## 前提

- 相机热点（SSID 形如 `S5-XXXXXX`）
- 本机实测该相机：**SSID `S5-XXXXXX` / 密码 `a70741470e23`**
- Mac 连上这个热点后，网关通常是 `192.168.54.1`

## 一条命令

```bash
cd "/Users/wuwilliam/Documents/ChatGPT/S5_逆向_项目总包_20261012/12_S5无线监看_v1.0_20261014"
/Users/wuwilliam/.dsh/dsh-runtimes/dsh-primary-runtime/dependencies/python/bin/python3 s5_selfcheck.py
```

脚本会自动找相机（先试 `192.168.x.x`，再试热点网关 `192.168.54.1`），然后：

1. 报相机当前模式（rec / play）
2. **★ 关键：测 rec 模式下 DLNA 内容树有没有内容** ← 这就是"边录边发"是否生效
3. 有内容就下载第一张验证

## 怎么读结果

| 输出 | 含义 | 下一步 |
|---|---|---|
| `内容条目数 = 0`，HTTP 200 | 有响应但**没内容** | 「边录边发」没生效，或该模式不支持此网络形态 |
| `HTTP 403` | **授权没到 `ok`**（不是模式问题） | 先跑监看工具拿 `ok`，再重跑本脚本 |
| `内容条目数 > 0` 🎉 | **「边录边发」生效** | 可在拍摄模式下无线取片 ⇒ 能实现"边录边套 LUT" |

## 重要：先在【家网】下试一次

**不用动 Wi-Fi，先在家网下把菜单里那个「一边录制一边发送图像」打开，然后跑：**

```bash
/Users/wuwilliam/.dsh/dsh-runtimes/dsh-primary-runtime/dependencies/python/bin/python3 \
  s5_selfcheck.py --cam 192.168.x.x
```

如果家网下就生效，那是最好的结果 —— **不用切热点、远程协助也能继续**。

## 附：一个值得留意的安全问题

```
MAC 地址 : 70:74:14:XX:XX:XX      ← 每个 Wi-Fi 信标里都有；相机的 UPnP UDN 里也有
热点密码 : a70741470e23
           └───────┘
           去掉首字母 a = 70741470e2 + 3
           MAC 前 10 位  = 70741470e2      ← 完全一致
```

**前 10 位完全相同。** 若这个规律成立，热点密码可从公开的 MAC 推算 ⇒ 范围内的任何人都能连上相机热点。

**但这只有 1 个样本，不能当结论。** 需要第二个样本（另一台 S5/S5M2 的 MAC + 热点密码），
或者用官方 LUMIX Sync 连接时抓热点协商过程来验证。建议记为
「**强相关，待验证**」，不要直接写成"密码可推导"。
